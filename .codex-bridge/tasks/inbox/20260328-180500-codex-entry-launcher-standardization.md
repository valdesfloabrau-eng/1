# Задача
Сделай практический автоматический запуск bridge при входе в Codex через единый стандартный launcher.

Работай только с проектом:
C:\Users\User\codex_github_bridge

# Цель
Пользователь должен запускать Codex через один стандартный входной файл/ярлык, который:
1. проверяет и при необходимости поднимает bridge
2. не создаёт второй worker
3. затем пытается открыть Codex
4. если надёжный запуск Codex app невозможен в этой среде, честно сообщает это и оставляет bridge поднятым

# Важная граница
Не делать хрупкий системный перехват любого возможного запуска Codex по всей Windows.
Не использовать registry hacks, Windows service, Task Scheduler, process watcher, глобальные alias-подмены.
Нужно сделать сильный и чистый пользовательский входной сценарий: один launcher/ярлык как стандартный способ входа.

# Что нужно сделать
1. Создай или обнови основной входной файл:
   C:\Users\User\codex_github_bridge\OPEN_CODEX.cmd

2. Если файла ещё нет — создай его.
   Если есть — сделай backup рядом.

3. OPEN_CODEX.cmd должен быть тонким wrapper и запускать PowerShell-скрипт:
   C:\Users\User\codex_github_bridge\worker\open-codex.ps1

4. Создай или обнови:
   C:\Users\User\codex_github_bridge\worker\open-codex.ps1

5. Логика open-codex.ps1:
   - проверить живой ли worker
   - если worker не жив, поднять bridge через существующий рабочий механизм
   - убедиться, что второй worker не создаётся
   - после этого попытаться открыть Codex безопасным способом
   - если надёжный запуск Codex app по-прежнему не получается, не валить bridge и не ломать схему; вместо этого:
     - оставить bridge поднятым
     - вывести пользователю понятное сообщение, что bridge готов, а Codex app нужно открыть вручную
   - записать подробный launcher log в runtime\logs

6. Не пытаться снова агрессивно чинить системный app launch.
   Разрешено:
   - использовать уже существующий наиболее надёжный способ запуска, если он реально работает
   - если он не работает, честно fallback'нуться к сообщению пользователю

7. Дополнительно создай удобный пользовательский ярлык на рабочем столе или в понятном месте, если это можно сделать локально и безопасно:
   - название, например: Open Codex (with Bridge)
   - ярлык должен ссылаться на OPEN_CODEX.cmd
   - если создание ярлыка небезопасно или неуместно в этой среде, не насилуй систему, просто зафиксируй это в отчёте

8. START_BRIDGE.cmd и STOP_BRIDGE.cmd не ломать.
   START_CODEX_WITH_WORKER.cmd оставить как legacy, если он уже есть.

9. После изменений выполни тесты:
   - Сценарий 1: worker не запущен -> OPEN_CODEX.cmd -> bridge поднимается -> второй worker не создаётся -> либо Codex открывается, либо пользователь получает понятный fallback message
   - Сценарий 2: worker уже запущен -> OPEN_CODEX.cmd -> bridge не дублируется -> либо Codex открывается, либо bridge остаётся живым и даётся fallback message

# Критерии приёмки
- существует OPEN_CODEX.cmd
- существует open-codex.ps1
- bridge автоматически поднимается при запуске OPEN_CODEX.cmd
- второй worker не создаётся
- если Codex app не удаётся открыть, bridge всё равно остаётся поднятым, а пользователю показывается понятное сообщение
- есть launcher log
- вне C:\Users\User\codex_github_bridge ничего не меняется, кроме допустимого пользовательского ярлыка, если он создан
